# 文化圏を跨ぐ関係を1本張るやり方（この手順だけで1本が終わる）

**この手順書は Sonnet が単独で1本を完了できる粒度で書いてある。** 設計の判断は済んでいるので、
調査する側は判断しない。迷ったら「未確認」と書いて次へ進む。**空欄を推測で埋めない。**

対象は **既にKBに在る movement 2件の間の関係1本**。新しい movement を作るタスクではない
（1件の調査は `docs/investigation-task.md`）。

## なぜこれをやるか

このKBは時間軸だけでなく**空間の広がりと関連性**を体系化するもの。だが `tools/audit.py` は
「他の文化圏の movement と1本も繋がっていない movement が 45/52件」と出す。文化圏ごとに
3件ずつ揃っていても、互いに繋がっていなければ13個の孤島が並んでいるだけになる。

---

## 手順

### 1. 与えられた2件を読む

```bash
python3 tools/bundle.py movement/<slug-a>
python3 tools/bundle.py movement/<slug-b>
```

**本文を最後まで読む。** 既に本文に書いてあることを関係として立て直すだけで済む場合がある
（その場合も出典は取り直す——本文の記述が二次要約止まりのことがある）。

### 2. 関係の「実体」を1つに絞る

**「影響を受けた」で終わらせない。** 何が動いたのかを1つ特定する。動くものは4つのどれか。

| 動いたもの | 例 | 関係の証拠になるもの |
|---|---|---|
| **人** | 画家・教師が土地を移った | 移動の年、着任・在籍の記録 |
| **物** | 作品・版画・写本が渡った | 収蔵記録、展覧会の出品目録 |
| **場** | 展覧会・万博・芸術祭で同席した | 開催年、出品者名簿 |
| **言葉** | 雑誌・翻訳・宣言が読まれた | 誌名と号、読んだ側の言明 |

**どれも押さえられないなら関係を張らない。**「同時代に似ている」は関係ではない
（時間と空間から機械が出す・`docs/schema.md`）。空振りは失敗ではないので、
何を探して無かったかを報告して終わる。

### 3. 関係語彙と `certainty` を決める

解釈を含む関係なので `certainty` と `source` が**必須**。

| 語彙 | 使うとき |
|---|---|
| `influenced_by` | Bが Aから受け取った（向きは受け取った側に書く） |
| `diffused_to` | Aの様式・技法がBの土地へ広がった |
| `responds_to` | Bが Aを踏まえて応答した（賛否を問わない） |
| `reacts_against` | Bが Aに反発して立った |

| `certainty` | 条件 |
|---|---|
| `attested` | **当事者本人の言明**。誰がどこで言ったかを本文に書けること |
| `scholarly` | 研究の通説。事典・美術館・査読論文が書いている |
| `hypothesis` | 自分の推論。**俯瞰の生成から除外される**ので、逃げ場として使わない |

**当事者の発言を二次資料の中で読んだだけなら `attested` にしない。** 原典（その人の著作・書簡・
講演録）に届いていないなら `scholarly` にして、本文に「原典は未確認」と書く。実例——
サンゴールがクロード・マッケイを「ネグリチュードの精神的な創設者」と呼んだ発言は、二次資料で
繰り返し引かれているが原典に届かなかったので `scholarly` にした
（[movement/negritude](../entities/movements/negritude.md)）。

### 4. 中継が要るかを判断する

AとBが直接繋がっておらず、**間に別の運動が挟まっている**ことがある。このとき
A→B の直接エッジを張ると、2段の連鎖を1段に潰して主張を強くしてしまう。

**中継が既にKBに在るなら、2本に分けて張る。** 実例——ダカール派はハーレム・ルネサンスから
直接影響を受けたのではなく、ネグリチュードを介している。だから
`ダカール派 --part_of--> ネグリチュード --influenced_by--> ハーレム・ルネサンス` の2本にした。

**中継がKBに無いなら、それを作るかどうかで止まって報告する。** 勝手に新しい movement を
作らない（1タスク1本の範囲を超える）。

### 5. 関係を書く

**エッジは受け取った側・応答した側のファイルに書く。** 逆向きは書かない（ビルドが両方向に
展開する・`docs/schema.md`）。

```yaml
relations:
  - {type: influenced_by, target: movement/<slug-a>, certainty: scholarly, source: "https://..."}
```

本文の `## 空間` に、**何が動いたのか**を書く。人なら誰がいつどこからどこへ、物なら何が
どこへ、場なら何年のどの催しか。`## 未着手` に、原典に届かなかったものを書く。

**担い手が2つの movement を実際に繋いでいるなら person を作ってよい**
（`docs/schema.md` の person 作成基準2）。ただし今回の1本に要るものだけ。名簿を作らない。

### 6. 検証を通す

```bash
python3 tools/build_graph.py --check
python3 tools/linkcheck.py entities/movements/<slug-a>.md entities/movements/<slug-b>.md
```

`linkcheck.py` は**必ず通す**。実測で、実在するページから別言語版のURLを組み立ててしまった例が
出ている（引用文は本物、URLは存在しない）。404 が出たら、そのURLを本当に開いたか思い出す。

`--check` が落ちる主な理由は `docs/investigation-task.md` の「6. 検証を通す」と同じ。

### 7. 報告する

- 張った関係（両端・語彙・`certainty`）
- 動いたものは何か（人／物／場／言葉のどれで、具体的に何か）
- 原典に届かなかったもの
- **空振りしたなら空振りと言う。**「何を探して、どこに無かったか」まで書く

## やらないこと

- **`overviews/` を触らない**（俯瞰の更新は aiko-art がやる）
- 他のエージェントが編集中のファイルを触らない。**自分の2件と、その2件が要求する person だけ**
- **`git checkout` / `git restore` / `git stash` を使わない**——他のエージェントと私の未コミットの
  編集を消す（2026-08-09 に実際に消えた）。生成物がおかしくなったら、そのまま報告して止まる
- **commit しない**（私がまとめて確認して commit する）
- 設計を変える（関係語彙を足す・`certainty` の定義を動かす）。必要だと思ったら
  [issue #1](https://github.com/masa-san-jp/art-history-notes/issues/1) にコメントして止まる
- 同時代の並行関係をエッジにする（時間と空間から機械が生成する）
